# Cageforge Python binding

`cageforge` provides a typed Python facade over the Cageforge cross-platform
sandbox. It resolves the same TOML profiles and uses the same native Linux,
macOS, and Windows enforcement backends as the Rust and JVM integrations.

The package is built with PyO3 and maturin. Python methods are synchronous by
design, while every native wait and stream operation releases the GIL. An
asyncio application can use `await cageforge.wait_for_async(process)` without
blocking its event loop.

## Install

```bash
python -m pip install cageforge
```

Each wheel contains the Python extension and the native helper resources for
one operating-system and architecture target. Linux wheels include the pinned
Bubblewrap resource. Windows setup remains an explicit administrator-approved
operation through `WindowsSetup`; creating a runtime never silently installs
system components.

## Quick start

```python
from cageforge import Cageforge, RuntimeContext

config = """
[profiles.default]
filesystem.read = ["minimal"]
"""

Cageforge.check_toml(config, context=RuntimeContext("/workspace"))
runtime = Cageforge.from_toml(config, context=RuntimeContext("/workspace"))
try:
    process = runtime.launch(["/bin/echo", "hello"])
    try:
        print(process.wait().exit_code)
    finally:
        process.close()
finally:
    runtime.close()
```

`launch()` with no arguments runs the selected profile command. An explicit
argv is passed directly to the backend; it is never interpreted as shell
syntax. `SandboxProcess` exposes `read_stdout`, `read_stderr`,
`write_stdin`, `try_wait`, `wait`, `kill`, and `close` for the same lifecycle
operations available in the JVM binding. Cancelling `wait_for_async()` also
terminates the sandbox boundary, matching the JVM async-wait contract.

The configuration model and policy semantics are documented in the workspace
[configuration guide](../../cageforge-config/examples/CONFIGURATION_GUIDE.md).
The Python surface is kept aligned with the JVM surface by the binding API
contract tests and by
the shared native smoke tests in CI.

## Development

From this directory, install maturin, build the extension with
`maturin develop`, run `pytest`, `mypy --strict`, and `ruff check`. The
committed `_cageforge.pyi` file is generated by `cargo run --bin stub_gen`;
CI fails when the generated API is stale.
